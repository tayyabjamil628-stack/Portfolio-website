## 1. Overview of Deployment Architecture

This website is designed for zero-server static hosting on AWS infrastructure. The setup utilizes Amazon Simple Storage Service (S3) for durable object storage, coupled with Amazon CloudFront as a global Content Delivery Network (CDN) to ensure low latency, SSL/TLS encryption via AWS Certificate Manager (ACM), and custom domain routing via Route 53.

## 2. Step-by-Step AWS Provisioning Guide

### Step 1: Create Amazon S3 Bucket
1. Open the AWS Management Console and navigate to **S3**.
2. Click **Create bucket**.
3. **Bucket Name:** `maliktayyabjamil-portfolio` (Must be globally unique).
4. **AWS Region:** Select `us-east-1` (N. Virginia) for optimal CloudFront integration.
5. **Block Public Access settings:** Keep "Block *all* public access" **CHECKED**. (Security Best Practice: Access will be restricted exclusively via CloudFront Origin Access Control).
6. Enable Bucket Versioning (Optional for deployment rollbacks).

### Step 2: Configure AWS CloudFront Distribution & Origin Access Control (OAC)
1. Navigate to **CloudFront** console and click **Create Distribution**.
2. **Origin Domain:** Select your S3 bucket (`maliktayyabjamil-portfolio.s3.us-east-1.amazonaws.com`).
3. **Origin Access:** Select **Origin access control settings (recommended)**.
4. Click **Create control setting** -> Name: `S3-OAC-Portfolio` -> Create.
5. **Viewer Protocol Policy:** Select **Redirect HTTP to HTTPS**.
6. **Allowed HTTP Methods:** `GET, HEAD`.
7. **Cache Key and Origin Requests:** Select `CachingOptimized`.
8. **Web Application Firewall (WAF):** Do not enable (or select default protection depending on budget).
9. **Default Root Object:** Set explicitly to `index.html`.
10. Click **Create Distribution**.

### Step 3: Apply S3 Bucket Policy
Copy the JSON policy generated by CloudFront and paste it into S3 -> Permissions -> Bucket Policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipalReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::maliktayyabjamil-portfolio/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::ACCOUNT_ID:distribution/DISTRIBUTION_ID"
        }
      }
    }
  ]
}
```

### Step 4: Configure ACM SSL Certificate & Route 53 DNS
1. Navigate to **AWS Certificate Manager (ACM)** in `us-east-1`.
2. Request a public certificate for `maliktayyabjamil.com` and `*.maliktayyabjamil.com`.
3. Perform DNS validation by adding the CNAME records provided by ACM into **Route 53**.
4. In CloudFront Distribution Settings -> Alternate Domain Names (CNAMEs): Add `maliktayyabjamil.com`. Select your ACM certificate.
5. In Route 53 Hosted Zone: Create an **A Record** with "Alias" toggled ON pointing to your CloudFront distribution domain name (`d111111abcdef8.cloudfront.net`).

## 3. Automated S3 Deployment Script (AWS CLI)

To deploy updates cleanly from your local environment or CI/CD runner:

```bash
#!/bin/bash
# AWS S3 Sync & CloudFront Invalidation Script

BUCKET_NAME="s3://maliktayyabjamil-portfolio"
DISTRIBUTION_ID="E1A2B3C4D5E6F7"

echo "🚀 Uploading static portfolio assets to AWS S3..."

# 1. Upload static CSS/JS/Assets with 1-Year Cache
aws s3 sync ./ $BUCKET_NAME \
  --exclude "index.html" \
  --exclude ".git/*" \
  --exclude "docs/*" \
  --exclude "screenshots/*" \
  --cache-control "public, max-age=31536000, immutable" \
  --delete

# 2. Upload index.html with No-Cache header to force instant deployment updates
aws s3 cp ./index.html $BUCKET_NAME/index.html \
  --cache-control "no-cache, no-store, must-revalidate" \
  --content-type "text/html"

# 3. Trigger CloudFront Edge Cache Invalidation
echo "⚡ Invalidating AWS CloudFront edge cache..."
aws cloudfront create-invalidation \
  --distribution-id $DISTRIBUTION_ID \
  --paths "/*"

echo "✅ AWS Deployment Complete! Site live at https://maliktayyabjamil.com"
```

## 4. Custom 404 Error Page Handler in CloudFront

In CloudFront -> Error Pages tab:
- **HTTP Error Code:** `404 Not Found`
- **Customize Error Response:** Yes
- **Response Page Path:** `/index.html` (or `/404.html`)
- **HTTP Response Code:** `200 OK` (or `404`)
